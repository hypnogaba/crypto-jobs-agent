# Crypto Jobs Agent — Повний опис проєкту

Цей документ — самодостатній опис усього проєкту: ідея, рішення, поточний стан, технічні знахідки. Розрахований на те, щоб інший агент/сесія міг підхопити роботу без читання всієї історії розмови.

## 1. Ідея продукту

Агент для пошуку роботи в крипті/web3. Людина заходить, одним реченням (або CV) описує, кого шукає. Щоранку отримує до п'яти можливостей — не список, а вже готові до дії картки: знайдена вакансія + пояснення "чому ти підходиш" + готова чернетка заявки/DM. Людина сама тисне "надіслати".

**Ключові принципи (не обговорюються):**
- Ніякого автоматичного подання — останній тап завжди робить людина
- Ліміт 5 карток/день назавжди, не пейвол
- Не job-борд, не LinkedIn, тільки крипта/web3
- Шляхи подачі деградують: людський (DM з чернеткою) → формальний (CV + cover letter)

Повний оригінальний продуктовий документ (розділи 1-12) обговорювався на початку проєкту, ключові витяги збережені в `docs/superpowers/specs/2026-07-28-crypto-hiring-agent-mvp-design.md`.

## 2. Роадмап (3 фази)

- **Фаза 1 (валідація)** — моніторинг hiring-сигналів тільки в X, чернетки в Telegram, один користувач (тестер). Мета: перевірити, чи вистачає сигналів і чи чернетки достатньо якісні. **Статус: виконано, 4 дні даних, див. розділ 3.**
- **Фаза 2** — розширення джерел (ATS API, крипто-борди), перехід на самостійний скрипт із власним Anthropic API ключем. **Не почато.**
- **Фаза 3** — повний продукт: сайт з онбордингом, CV-парсингом, щоденною пачкою карток, кількома юзерами. **Код написано й протестовано локально, деплой заблокований — див. розділ 4.**

## 4. Фаза 3 — сайт: що зроблено і де застрягли

### Що готово (код у `web/`)

- Next.js 16 + TypeScript, Tailwind, App Router
- MySQL через Prisma (driver adapter `@prisma/adapter-mariadb` — обов'язковий у Prisma 7, звичайний конструктор без адаптера більше не працює)
- Сторінки: онбординг (`/`) → дашборд карток (`/dashboard`) → налаштування доставки (`/settings`)
- Mock AI-шар (`src/lib/ai.ts`) — CV-парсинг і генерація чернеток працюють на заглушках, $0 витрат, легко замінити на реальний Anthropic API (просто прибрати `if (!hasRealApiKey)` гілку)
- Delivery-шар (`src/lib/delivery.ts`) — вибір Telegram/email, Telegram уже робочий
- Повний флоу протестовано локально в браузері (`npm run dev`) — онбординг → запис у базу → дашборд → налаштування, усе працює

### Де застрягли: деплой на shared-хостинг (shared-хостинг)

Користувач хоче деплоїти на власний власний shared-хостинг (ADM.TOOLS/CloudLinux, shared, НЕ Vercel — свідомий вибір, не помилка). П'ять підтверджених технічних бар'єрів:

1. **Node.js Selector не встановлений** — адмінська функція CloudLinux, не вмикається з боку акаунту користувача
2. **CPU-throttling білду** — `next build` на сервері: 2.5 год wall-clock, 12 сек реального CPU-часу (акаунт повністю оплачений, не тріал)
3. **Навіть легкий standalone-runtime сам помирає** за ~10-20 сек без явної причини в логах (root-доступу немає, щоб побачити чому). Голий Node-скрипт (без Next.js) виживає нормально — проблема специфічна для Next.js-процесу
4. **Довільні зовнішні порти заблоковані фаєрволом** — тільки 80/443/3306(MySQL)/21(FTP)/22(SSH) відкриті
5. **SSH crontab зламаний** — Python-помилка в обгортці CloudLinux (`cloudlinux-user-cron`), треба через веб-панель ("Розклад завдань")

Повний технічний розбір з командами й доказами: `docs/shared-hosting-findings.md`.

**Що працює там:** MySQL (швидкий, стабільний, зовнішньо доступний), PHP 8.2 (нативний стек), FTP, статичні файли.

**Рішення, на якому зупинились:** переписати сайт на **PHP** замість Next.js/Node — єдиний стек, який цей хостинг реально підтримує без обмежень. План:
- Onboarding-форма → звичайний `$_POST` + PHP
- Prisma → прямий `mysqli`/`PDO` до тієї самої вже робочої MySQL-бази
- Telegram-доставка → `curl` з PHP (уже підтверджено, що зовнішні HTTPS-запити з сервера працюють)
- Email-доставка → вбудована `mail()` PHP замість Resend (щоб не платити за ще один сервіс)
- Щоденний cron → PHP CLI-скрипт через панельний "Розклад завдань" (не персистентний процес — саме такий патерн стабільно працює на цьому хостингу)

**PHP-переписування ще не почато.**
