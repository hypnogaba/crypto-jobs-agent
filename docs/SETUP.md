# Що потрібно від власника

Система працює. Три речі лишаються за тобою — кожна вмикає окремий шматок.

## 1. Токен Telegram-бота → вмикає доставку

Створити бота: `@BotFather` → `/newbot` → назва **NextRole** → юзернейм **mynextrole_bot**.

Потім три команди (токен **не вставляй у чат**, лише в термінал):

```bash
cd web
npx wrangler secret put TELEGRAM_BOT_TOKEN        # вставити токен від BotFather
npx wrangler secret put TELEGRAM_BOT_USERNAME     # mynextrole_bot, без @
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET   # вигадати довгий випадковий рядок
```

Зареєструвати вебхук тим самим секретом:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -d "url=https://nextrole.hypnogaba.workers.dev/api/telegram/webhook" \
  -d "secret_token=<ТОЙ САМИЙ СЕКРЕТ>"
```

Токен також потрібен на сервері, де крутиться доставка:

```bash
# Токен НЕ в командному рядку: він лишився б в історії shell і в журналі sshd.
# Файл створюється з правами 600, значення йде через stdin.
printf 'TELEGRAM_BOT_TOKEN=%s\n' '<ТОКЕН>' | ssh root@<сервер> \
  'umask 077; touch /etc/nextrole-scanner.env; chmod 600 /etc/nextrole-scanner.env; cat >> /etc/nextrole-scanner.env'
```

**Вебхук закритий за замовчуванням.** Поки секрет не заданий, він відповідає 401
на будь-який запит. Це навмисно: інакше на свіжому деплої хтось міг би слати
оновлення від імені Telegram.

## 2. Токен Cloudflare із правом на зони → вмикає домен

Наявний OAuth-логін wrangler уміє D1 і Workers, але **зони лише читає**.
Потрібен Custom Token:

```
dash.cloudflare.com → My Profile → API Tokens → Create Custom Token
  Account · Zone · Edit          ← саме це дає право створювати зони
  Zone    · DNS  · Edit
  Zone    · Zone · Edit
```

Далі я створю зону `nextrole.info`, візьму видані Cloudflare nameserver'и
й пропишу їх на Porkbun через API — доступ до Porkbun уже є й перевірений.

### ⚠ Це блокує роботу сканера просто зараз

Сканер на сервері працює на **тимчасовому OAuth-токені wrangler**, який діє
близько години. Він **уже зупиняє прогони** — за одну сесію розробки протух
чотири рази.

Самооновлення тут неможливе, я перевірив:
- refresh-токен Cloudflare **одноразовий і ротується** — сервер і твій локальний
  wrangler ділили б один токен, і хто оновить першим, зламав би іншого;
- сам wrangler оновлює доступ **лише в пам'яті свого процесу** й не записує
  новий токен у конфіг, тому витягти довгоживучий креденшл звідти нема звідки.

Тому потрібен саме **постійний API-токен**. Той самий Custom Token, що дає
право на зони для домена, має нести ще й `Account · D1 · Edit`:

```
dash.cloudflare.com → My Profile → API Tokens → Create Custom Token
  Account · D1        · Edit     ← оживляє сканер
  Account · Zone      · Edit     ← дає створити зону nextrole.info
  Zone    · DNS       · Edit
  Zone    · Zone      · Edit
```

Покласти в `/etc/nextrole-scanner.env` замість `CF_API_TOKEN`. API-токени
не протухають.

## 3. Ключ Anthropic → покращує якість

Продукт працює й без нього: розбір профілю та підбір **детерміновані**.
Ключ лише робить пояснення «чому підходить» людськішими і вмикає переклад
назви й опису вакансії мовою людини (кеш у `job_i18n`, міграція 0013).

```bash
cd web && npx wrangler secret put ANTHROPIC_API_KEY
printf 'ANTHROPIC_API_KEY=%s\n' '<КЛЮЧ>' | ssh root@<сервер> \
  'umask 077; chmod 600 /etc/nextrole-scanner.env; cat >> /etc/nextrole-scanner.env'
```

Вартість: ранжування на Haiku ≈ $0.10 на людину в місяць.

## Хто адмін

**Обов'язковий крок.** Адмінку не бачить ніхто, доки ти не назвеш власника явно:

```bash
cd web && npx wrangler secret put ADMIN_CHAT_ID   # твій chat_id у Telegram
```

Свій `chat_id` бот покаже сам — він приходить у кожному оновленні від тебе.

Раніше запасним варіантом був «перший зареєстрований акаунт». Відколи вхід не
питає пошти й пароля, першим акаунтом стає перший випадковий відвідувач сайту,
тож цей запасний варіант прибрано. `ADMIN_EMAIL` лишається для сумісності, але
без пошти в акаунтах він ні з чим не збігається.

## Лічильник відвідувань

Cloudflare Web Analytics, сайт `nextrole.info` в акаунті. Маячок ставить
`web/src/app/analytics.tsx`, токен лежить відкрито у `vars` у `wrangler.jsonc`
— він і так видимий у HTML і вміє лише слати перегляди.

Режим у панелі Cloudflare має лишатись **«Enable with JS Snippet
installation»**. Варіант «Enable» (автоматичне вбудовування) на цьому сайті не
працює: сторінки віддає Worker, і скрипт у HTML не з'являється. Якщо колись
увімкнути обидва способи одночасно, кожен перегляд рахуватиметься двічі.

Дивитись: Cloudflare → Analytics → Web analytics → nextrole.info.

## Історія версій в адмінці

Список змін у панелі власника збирається з комітів. Пам'ятати про це не
треба: `npm run cf:deploy` і `npm run preview` запускають збірку списку самі
першим кроком.

```bash
cd web && npm run releases   # окремо — лише якщо треба оновити список без деплою
```

Скрипт переписує `web/src/lib/releases.ts` (30 днів історії). Воркер не має
git, тому без цього кроку панель показувала б історію станом на попередній
деплой. Наслідок, який варто знати: після деплою `git status` показує змінений
`releases.ts` — це нормально, його треба закомітити разом із рештою.
