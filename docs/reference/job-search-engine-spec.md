# Job-Search Engine — референс-контракт рушія

> **Джерело:** приватний job-search агент, що вже працює в проді (щоденний cron + watchdog).
> **Навіщо цей файл тут:** Plan 2 (Scan Worker) і Plan 3 (Match Worker) цього репо портують саме
> цю логіку в TypeScript на Cloudflare Workers. Це референс-контракт поведінки, не опис коду репо.
> Дизайн-рішення, що з нього випливають, — у
> `docs/superpowers/specs/2026-08-20-general-job-search-saas-design.md`.
>
> **Приватність:** усі особисті дані (кар'єрний профіль, локація, шляхи інфраструктури,
> ідентифікатори джобів і воркспейсів) свідомо не входять у цей файл — вони лишаються локально
> в `docs/reference/job-search-engine-spec.private.md`, який ігнорується git'ом.

## 1. Архітектура запуску

Три періодичні джоби:

| Джоб | Розклад | Призначення |
|---|---|---|
| Основний скан | Пн–Пт, 05:00 локального часу | Повний прогін драбини джерел. Сб/Нд — тиша |
| Watchdog | Пн–Пт, 08:00 | Механічна перевірка результату скану |
| Weekly digest | Понеділок | Зведення за минулий тиждень |

### Урок про рантайм джоба

У вихідній системі cron API форс-інжектить дефолтний `toolsAllow` (`toolsAllowIsDefault: true`),
який не чиститься навіть явним `null`. Рантайм агента падає з `cannot enforce runtime toolsAllow`
приблизно за 6 секунд — тобто ізольований запуск помирає **тихо**, без жодного сигналу.
Робочий обхід — запуск типу `systemEvent → main`, у який ця інжекція не потрапляє.

Для порту на Cloudflare Cron Trigger це не відтворюється дослівно, але переносить головне:
**прогін мусить лишати слід свого завершення, інакше тиха смерть нерозрізненна від «нічого не знайшли»**.

### Watchdog — enforcement за результатом

Перевіряє не «чи запустився джоб», а **скільки distinct-компаній із живими URL видав скан сьогодні**.
Флор = 5. Якщо не запустився АБО видав <5 distinct → форс-ран основного джоба + proof-of-work нота.

**Головний урок для продукту:** ніколи не дозволяй зламаній автоматизації впасти тихо.
Enforcement має бути result-based, а не «агент відчув насичення».

## 2. Дві колії пошуку

Рушій веде дві незалежні колії, кожна зі своїм варіантом резюме:

- **Track A — не-крипта.** Географічно прив'язана колія: цільовий регіон **або** remote,
  придатний для роботи з цього регіону. Вбирає AI/deep-tech, fintech, defense-tech,
  та location-agnostic організації (NGO, фонди, наддержавні інституції).
- **Track B — крипта / web3.** Remote будь-де. Ecosystem, partnerships, BD, community, DevRel.
- **Side income** — легкий футер (хакатони, гранти під технічний скіл), **не третя колія**.

Конкретні регіони, ролі та профілі резюме — параметри користувача, а не константи рушія.
У продукті вони приходять із `profiles` у D1; у вихідному боті були захардкожені під одного власника.

## 3. Фільтри (hard gates)

**Локація**
- Жодного hard-lock на одне місто.
- Приймається будь-який remote — global, US, EU, APAC.
- Web3-колія = remote anywhere.
- Location-agnostic організації — локація не важить взагалі.
- Цільове місто важить **лише** для onsite/hybrid без remote-опції.

**Reject**
- Onsite-only у місті поза цільовим регіоном без remote.
- Relocation-only.
- Чиста quota-sales / AE.

**Інше**
- Свіжість: ≤14 днів. Дедуп проти трекера.
- **Без фільтра за зарплатою** — comp-gate знято свідомо (відсікав забагато валідних ролей).
- Marketing in-scope, але ≤⅓ виводу. Партнерства / ecosystem / BD / ops / DevRel / program / GTM /
  AI-agent — пріоритетніші за генерик-маркетинг.
- Локальні національні джоб-борди виключені як джерело; роботодавці з того ж регіону — ок.

## 4. Ескалаційна драбина R1–R5 (self-reconfigure)

«Насичення» / «нічого нового» — **не прийнятний результат**. Якщо distinct-компаній (A+B) < 7,
агент сам лізе по щаблях:

| Щабель | Джерело |
|---|---|
| **R1** | Стендові ATS — слаги Ashby / Greenhouse / Lever по списку компаній + AUTO-GROW |
| **R2** | Безкоштовні API-агрегатори: Arbeitnow, Remotive, RemoteOK, HN «Who is hiring» |
| **R3** | Getro ecosystem API: `POST api.getro.com/api/v2/collections/<id>/search/jobs` (Solana = 858) |
| **R4** | Discovery-by-role: 4–6 ротаційних role-keyword запитів по бордах на **нові** фірми |
| **R5** | Агент сам вигадує 3–5 нових живих джерел |

**AUTO-GROW.** Нова фірма, що дала фіт → додається в секцію `STANDING COMPANIES` трекера, яка
читається на старті кожного прогону. Список джерел росте сам.

**SELF-REPAIR.** Джерело down ≥2 дні → `deprecated` + автозаміна. Broken source (404 / 403 /
Cloudflare / 410 / 406) → «джерело недоступне», і це **не рахується за порожній день**.

**PROOF-OF-WORK.** Якщо прогін повертає 0 — показати, які щаблі та джерела пройдено.

**Стендові ATS-компанії (робочий seed).**
Не-крипта: Datadog, Remote.com, Elastic, Supabase, H, lemlist, Nivoda, n8n, Synthesia, Doctolib,
Mistral, ElevenLabs, Filigran, Helsing, Auterion.
Крипта: Solana Foundation, Squads, CoW DAO, Solflare, Ondo, Trust Wallet, Yo Labs, Kraken.

## 5. OUTPUT-контракт (5 правил, зверху промпту)

- **O1 — голі URL, ніколи markdown `[text](url)`.** Цільовий канал доставки стрипить
  markdown-лінки, і виходить «немає лінків». Формат:
  `• Company — Role — location — why`, тоді повний `https://…` на **наступному** рядку.
  Немає URL → рядок викидається.
- **O2 — фіксовані секції завжди присутні** й перевірені через ATS. 0 фітів → **один** рядок із
  лічильником поспіль: `<секція> — немає сьогодні (N-й день)`. Лічильник живе в трекері:
  +1 за порожній день, reset у 0 при першому фіті. **Не** дампити список перевірених компаній.
- **O3 — ніколи не питати дозволу і не відкладати** («додам за запитом»). Звіт self-contained.
- **O4 — quality > speed.** Нічний прогін, вільні ліміти — обмести всі гілки й компанії
  до форматування.
- **O5 — self-check перед відправкою:** усі секції є? голий URL на кожному рядку?
  усі гілки ATS-swept?

**ONLY-FITS.** У канал доставки йдуть лише ролі, що пройшли всі фільтри. Rejects, dedupe і
watchlist — **лише** в трекері та архіві, не в повідомленні.

## 6. Анти-концентрація

- **GEO-CLONE dedup:** та сама роль по різних країнах = один рядок.
- **Max 2 ролі на компанію** в звіті, решта → `+N ще`.
- **KPI = distinct-company count** (`N ролей / M різних компаній`, ціль ≥7), не сирий volume.
- **COOLDOWN:** компанія, що з'явилась ≥3× за 7 днів, показує нові ролі лише за умови
  apply-first-strong фіту.

## 7. Стан джерел

**X / Twitter — вимкнено (2026-08-20).**
Провайдер `ai.6551.io` (`opentwitter` MCP) повністю запейволений — 402 на всіх ендпоінтах, плюс
0 придатних вакансій за місяць роботи. Альтернатива для повернення — прямий `twitterapi.io`
(~$0.15 за 1k), визнано не вартим. Це прямо суперечить висновку Фази 1 цього репо, яка була
побудована цілком на X-сигналах.

**LinkedIn** — немає API / доступу, scrape-block. **Не фабрикувати лінки.** Best-effort лише через
web search `site:linkedin.com/jobs`.

**Спільний ліміт-пул.** Бот ділить один LLM-пул із інтерактивним юзиджем власника. Тому скан
вночі + light mode — щоб не конкурувати за ліміти вдень. У продукті це знімається: один спільний
скан обслуговує всіх юзерів, дорога частина — лише per-user ранжування.

## 8. Персистенс

- **Трекер** (markdown-файл): dedup-база, лічильники порожніх днів, `STANDING COMPANIES`, run-логи.
  У продукті розкладається на `jobs_cache` + `sent` + `sources_state` у D1.
- **Архів** (Notion): денні сторінки + тижневі дайджести.
- **Ран-логи** окремим файлом.
