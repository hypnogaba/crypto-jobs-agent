# Повний план реалізації

Один документ, який відповідає на всі питання до початку роботи: як система
влаштована, як людина підключає Telegram, звідки береться достатньо джерел,
що бачить власник в адмінці, як виглядає щоденне повідомлення, і що треба
зробити тобі особисто.

---

# Частина I. Слабке місце — джерела

Твоє зауваження було найважливішим. Я його перевірив вимірюваннями, і відповідь
виявилась протилежною до очікуваної.

## 1.1 Джерел не мало — вони приховані

«31 джерело» — це неправильна одиниця виміру. Правильна — **скільки компаній ми
опитуємо напряму**, бо кожна компанія з робочим ATS це окреме джерело, яке ніколи
не блокується і дає посилання прямо до роботодавця.

Три вимірювання, зроблені 27 серпня:

| Що перевіряв | Результат |
|---|---|
| Скільки колекцій Getro живі | 15 із 40 перевірених id у діапазоні 20–2400 → **оцінка ~890 живих колекцій** |
| Скільки в колекції прямих ATS-лінків | **80%** (16 із 20 на першій сторінці Solana) |
| Чи вгадується ATS-слаг із назви компанії | **45%** — 27 влучань із 60 назв, узятих з агрегаторів |

Останнє найцінніше. Береш будь-яку назву компанії з будь-якого агрегатора,
перетворюєш на слаг, стукаєш у три ATS — і майже в половині випадків отримуєш
постійне пряме джерело. Серед влучань першого ж прогону: Zscaler (350 вакансій),
Remote.com (206), BetterHelp (202), DeepL (63).

## 1.2 Три механізми, які множать джерела

**Механізм 1 — перебір колекцій Getro.** Кожна колекція це екосистема фонду або
мережі: Solana, a16z, Index, лікарські мережі, ізраїльські фонди. Приблизно 890
живих колекцій, у кожній десятки компаній, 80% із прямим ATS-лінком. Перебирається
один раз, далі оновлюється.

**Механізм 2 — вгадування слага.** Кожна назва компанії, побачена будь-де —
в агрегаторі, у треді HN, у колекції Getro — перетворюється на слаг і перевіряється
у Greenhouse, Lever, Ashby, Workable, SmartRecruiters. Влучання 45%.

**Механізм 3 — список росте назавжди.** Кожне влучання зберігається. Компанія,
знайдена один раз, опитується щодня прямо, без посередників, і більше ніколи не
губиться.

## 1.3 Скільки джерел буде насправді

| Момент | Компаній-джерел | Звідки |
|---|---|---|
| День 1 | ~30 | Стартовий список |
| Тиждень 1 | ~400 | Перебір колекцій Getro |
| Місяць 1 | ~2 000 | Плюс вгадування слагів з усіх агрегаторів |
| Далі | росте щодня | Кожна нова назва — шанс 45% на постійне джерело |

Дві тисячі HTTP-запитів на добу — для сервера це кілька хвилин роботи. Ліміту немає.
Обмеження лише ввічливість: не більше кількох запитів на секунду до одного провайдера.

## 1.4 Ротація, коли компаній стане багато

Не всі дві тисячі треба опитувати щодня.

- **Щодня** — компанії, які за останні 30 днів дали хоч комусь збіг.
- **Раз на тиждень** — решта, рівномірно розкидані по днях.
- **Раз на місяць** — ті, що пів року не давали жодного збігу. Три місяці поспіль
  порожні — вибувають зі списку.

## 1.5 Маршрутизація за нішами

Ти правильно сказав: для web3 треба шукати в одних місцях, для решти IT — в інших.

Кожне джерело має теги, і кожна вакансія успадковує теги свого джерела плюс отримує
власні з назви посади.

| Ніша | Основні джерела |
|---|---|
| **Web3 і крипта** | Getro-колекції крипто-екосистем, CryptocurrencyJobs, прямі ATS крипто-компаній |
| **AI та deep-tech** | Getro-колекції AI-фондів, ATS модельних лабораторій, Arbeitnow, Landing.jobs |
| **Загальна інженерія** | Прямі ATS (найбільший обсяг), Arbeitnow, Himalayas, Jobicy, The Muse |
| **Продукт і дизайн** | The Muse, Welcome to the Jungle, прямі ATS |
| **DevRel і спільнота** | Getro, крипто- та AI-екосистеми, HN |
| **Партнерства і BD** | Прямі ATS, Getro, The Muse |
| **Тільки віддалено** | RemoteOK, Remotive, We Work Remotely, Working Nomads, NoDesk, Jobspresso |
| **Європа** | Arbeitnow, Landing.jobs, Welcome to the Jungle, Personio |
| **США** | Adzuna, The Muse, USAJobs, прямі ATS |

Маршрутизація працює **на етапі підбору, не сканування**. Скануємо все в один
спільний кеш; профіль людини вирішує, які теги брати до уваги. Так одна людина
з web3-профілем і друга з фінтех-профілем обслуговуються тим самим сканом.

## 1.6 Що робимо з мертвими джерелами

Порядок дій, коли джерело віддає 400/403/406:

1. **Перевірити заголовки.** Getro повертав 406 лише через відсутній `Accept` —
   джерело роками вважалося мертвим помилково. Спершу завжди перевіряємо це.
2. **Пошукати RSS або sitemap.** У Web3.career немає RSS, але `sitemap.xml` віддає 200.
3. **Пошукати офіційний API з безкоштовним ключем.** Adzuna замість Indeed.
4. **Обійти через ATS.** Компанію бачимо будь-де — вакансію беремо з її власного ATS.
   Так закривається LinkedIn, який не парситься ніколи.
5. **Якщо нічого не допомогло** — джерело позначається мертвим, і рівень R5 драбини
   шукає йому заміну автоматично.

# Частина II. Дизайн системи

## 2.1 Загальна схема

```
      ЛЮДИНА                          ВЛАСНИК
         │                               │
    ┌────┴─────┐                    ┌────┴────┐
    │  Сайт    │  ←── один акаунт ──│ Адмінка │
    │ Telegram │                    └────┬────┘
    └────┬─────┘                         │
         │                               │
    ┌────▼───────────────────────────────▼────┐
    │        База даних (Cloudflare D1)        │
    │  профілі · кеш вакансій · відправки      │
    │  компанії · здоров'я джерел · прогони    │
    └────▲───────────────────┬────────────────┘
         │                   │
   ┌─────┴──────┐      ┌─────▼──────┐      ┌──────────┐
   │   Скан     │      │   Матчер   │─────▶│ Доставка │
   │ 05:00 щодня│      │ 06:00 щодня│      │  07:00   │
   └─────┬──────┘      └────────────┘      └────┬─────┘
         │                                       │
   ┌─────▼──────────────────────┐          ┌─────▼─────┐
   │ Джерела: ATS компаній,     │          │  Telegram │
   │ агрегатори, RSS, Getro     │          └───────────┘
   └────────────────────────────┘
```

## 2.2 Складові

| Частина | Що робить | Де живе |
|---|---|---|
| **Сайт** | лендинг, онбординг, кабінет, чотири мови | Cloudflare Workers |
| **Адмінка** | стан джерел, ключі, компанії, ручні прогони | той самий сайт, окремий вхід |
| **Бот** | повний онбординг у чаті, доставка, керування | Telegram |
| **База** | усе, що треба пам'ятати | Cloudflare D1 |
| **Скан** | драбина джерел, наповнює спільний кеш | сервер, systemd-таймер |
| **Матчер** | шортліст → ранжування → топ-5 із поясненнями | сервер |
| **Доставка** | п'ять карток у Telegram, повтор при збої | сервер |

## 2.3 Дані

Дев'ять таблиць. Названі так, щоб призначення читалось без коментарів.

| Таблиця | Що зберігає |
|---|---|
| `users` | акаунт: `telegram_chat_id`, email (якщо реєструвався на сайті), мова, статус, **часовий пояс і обрана година доставки**, дата останньої взаємодії |
| `profiles` | відповіді на три питання: сфери, локація й режим, зарплата, теги індустрій, розібраний текст CV. Рівень прибрано 30.08 — див. ROADMAP |
| `jobs_cache` | спільний кеш вакансій: URL, компанія, посада, локація, віддалено, теги, джерело, дата публікації |
| `sent` | що кому й коли відправлено, текст «чому підходить», статус доставки |
| `companies` | постійний список роботодавців: слаг, який ATS, теги ніш, коли востаннє дав збіг |
| `sources_state` | здоров'я кожного джерела: статус, остання вдала відповідь, дні падінь, текст помилки |
| `source_keys` | ключі доступу, введені в адмінці (Adzuna, Reed, Jooble, USAJobs) |
| `scan_runs` | історія прогонів: скільки компаній, до якого рівня драбини дійшло, що було недоступне |
| `feedback` | реакція на добірку цілком — «не те» або «ще п'ять». Рівень добірки, не окремої вакансії |

## 2.4 Ідентичність акаунту

Це важливо, бо входів два.

**`telegram_chat_id` — основна особа акаунту.** Вебсесія прив'язується до неї.
Людина, яка почала в боті й потім відкрила сайт, потрапляє у той самий профіль,
а не в новий.

Email потрібен лише тим, хто реєструвався на сайті й ще не підключив Telegram.
Після підключення email лишається як запасний спосіб входу.

# Частина III. Як людина підключає Telegram

Два сценарії. Обидва мають привести в один акаунт.

## 3.1 Почала на сайті

```
1. Пройшла онбординг на сайті → створився профіль без Telegram
2. Натиснула «Підключити Telegram»
   → генерується одноразовий токен, живе 15 хвилин
   → показується кнопка на t.me/наш_бот?start=ТОКЕН
3. Тисне кнопку → Telegram відкриває чат із ботом → тисне Start
4. Бот отримує /start ТОКЕН
   → вебхук перевіряє секретний заголовок від Telegram
   → знаходить профіль за токеном, записує chat_id, гасить токен
5. Бот одразу пише: «Готово. Перша добірка завтра о 07:00»
6. Сторінка сама оновлюється й показує «Підключено»
```

**Захист.** Токен одноразовий і живе 15 хвилин. Вебхук приймає запити тільки
з секретним заголовком, який знає лише Telegram — інакше сторонній міг би
перехопити чужий токен і привласнити акаунт.

## 3.2 Почала в боті

```
1. Відкрила бота будь-де → тисне Start (без токена)
2. Бот веде той самий онбординг у чаті:
   — «Розкажи одним реченням, яку роботу шукаєш. Або надішли своє CV файлом»
   — розбирає відповідь, показує заповнену форму кнопками
   — людина править те, що не так, тисне «Все вірно»
3. Акаунт створюється одразу з chat_id. Нічого підключати не треба
4. Захоче на сайт → пише боту /site → отримує одноразове посилання для входу
```

CV файлом у Telegram працює: бот отримує документ, витягує текст, розбирає в ті
самі чотири поля.

## 3.3 Що людина може зробити в боті далі

| Команда | Дія |
|---|---|
| `/profile` | показати профіль, змінити будь-яке з чотирьох полів |
| `/pause` та `/resume` | зупинити й відновити щоденні добірки |
| `/more` | дати ще п'ять вакансій зараз, якщо сьогоднішні не підійшли |
| `/site` | одноразове посилання для входу на сайт |
| `/language` | перемкнути мову |
| `/time` | змінити годину доставки |
| `/delete` | видалити акаунт і всі дані |

# Частина IV. Що бачить людина щоранку

Повідомлення має бути **красивим і зрозумілим** — це те, заради чого весь продукт.

```
Доброго ранку. П'ять вакансій на сьогодні.

━━━━━━━━━━━━━━━━━━━━━━━━━━

1 · DeepL — Partnerships Manager
    Берлін або віддалено в ЄС · €85–110k

    Чому ти: шукають людину на партнерства
    в AI-продукті — це рівно твій профіль,
    і вони відкриті до повністю віддаленої
    роботи.

    https://jobs.ashbyhq.com/deepl/8f2a...

━━━━━━━━━━━━━━━━━━━━━━━━━━

2 · Alchemy — Ecosystem Lead
    Віддалено, будь-де · вилку не вказано

    Чому ти: web3-інфраструктура, робота
    з розробниками спільноти — збігається
    з твоїм досвідом у DevRel.

    https://jobs.ashbyhq.com/alchemy/3c1b...

━━━━━━━━━━━━━━━━━━━━━━━━━━

        ... ще три вакансії ...

━━━━━━━━━━━━━━━━━━━━━━━━━━

Сьогодні переглянуто 1 847 вакансій
у 312 компаніях.

[ Не те, що треба ]  [ Ще п'ять ]
```

**Час доставки обирає людина.** За замовчуванням 07:00 у її часовому поясі — пояс
визначається автоматично з браузера або з Telegram. Змінити можна в профілі чи командою
`/time`. Це не п'яте питання онбордингу: людина нічого не вводить, поки сама не захоче
змінити.

**Автопауза через 14 днів тиші.** Якщо два тижні немає жодної взаємодії — ні кнопок,
ні команд — бот пише одне повідомлення «ще шукаєш роботу?». Без відповіді ще три дні
акаунт стає на паузу. Відновити одним дотиком. Це економить гроші й знижує ризик,
що Telegram визнає бота розсильником.

**Правила оформлення, які не обговорюються:**

- **Голе посилання окремим рядком.** Telegram ріже markdown-лінки в деяких клієнтах,
  і людина бачить текст без посилання. Тому URL завжди відкритим текстом.
- **Вакансія без робочого посилання не показується.** Мертвий лінк руйнує довіру
  швидше, ніж порожній день.
- **«Чому ти» — одне-два речення про цю людину**, не переказ вакансії.
- **Чесність про зарплату.** Немає вилки — так і пишемо, не вигадуємо.
- **Рядок про обсяг роботи** внизу: скільки переглянуто. Показує, що система працювала.
- **Порожній день не мовчить.** Якщо знайшлось менше п'яти — надсилаємо скільки є
  з поясненням: «сьогодні менше, ми копали глибше». Тиша неприпустима.
- **Дві кнопки на всю добірку** — «не те» вчить систему, «ще п'ять» дає добірку одразу.
  Оцінки кожної окремої вакансії немає: свідоме спрощення. Наслідок чесно —
  сигнал грубий, тому підбір покращуватиметься повільніше, ніж міг би. Якщо після
  запуску виявиться, що якості бракує, оцінка кожної вакансії це найдешевший наступний крок.

# Частина V. Адмінка

Окремий вхід, доступний лише тобі.

| Екран | Що на ньому | Навіщо |
|---|---|---|
| **Огляд** | скільки вакансій і компаній сьогодні, скільки людей отримали добірку, скільки джерел упало | Стан системи за десять секунд |
| **Джерела** | кожне джерело: статус, остання вдала відповідь, дні падінь, текст помилки, скільки дало сьогодні. Кнопка «перевірити зараз» — запит іде живцем | Побачити й полагодити те, що зламалось |
| **Додати джерело** | вставив ендпоінт → «перевірити» → якщо віддає вакансії, зберігається й одразу в роботі | Розширювати каталог без коду й деплою |
| **Ключі** | поле для токена там, де джерело його потребує. Ввів ключ — джерело ожило | Adzuna, Reed, Jooble, USAJobs вмикаються за хвилину |
| **Компанії** | постійний список: скільки всього, які додались самі, які давно нічого не дають. Додати вручну | Керувати головним активом системи |
| **Прогони** | по днях: компаній, вакансій, до якого рівня драбини дійшло, які джерела були недоступні | Побачити, чи система деградує |
| **Люди** | скільки зареєстровано, скільки активних, скільки на паузі. Без перегляду чужих CV | Розуміти зростання |
| **Запустити зараз** | ручний скан, матчинг або доставка | Перевірити зміну одразу, не чекаючи ранку |

Адмінка з'являється **одразу після запуску скану**, а не наприкінці — щоб стан
системи було видно з першого дня.

# Частина VI. Що потрібно від тебе

Твої кроки. Без них система не запуститься — усе інше я зроблю сам.

## Перед початком роботи

| № | Що зробити | Де | Скільки часу |
