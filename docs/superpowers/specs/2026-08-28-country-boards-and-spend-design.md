# Національні борди, країна людини та панель витрат

Дата: 2026-08-28

## Задача

Продукт міжнародний, але джерела глобально-англомовні. Людина з України
отримує американські віддалені вакансії, бо українських дошок ми не читаємо.
Окремо: власник не бачить, скільки система витрачає.

## Що з'ясовано розвідкою

**DOU працює.** RSS, приблизно 25 вакансій на категорію, близько двадцяти
категорій. Djinni відповідає, work.ua блокує ботів.

**France Travail** — офіційний API державної служби зайнятості, безкоштовний,
потребує реєстрації. Найбільший інвентар у Франції. APEC вимагає POST,
HelloWork лише HTML.

**Web3 — не проблема джерел.** Великі компанії давно на звичайних ATS:
Coinbase 184 вакансії на Greenhouse, Ripple 126, Fireblocks 69. Ми їх уже
маємо. У кеші 458 web3-вакансій зі 118 компаній. Superteam Earn —
94% баунті й грантів, як джерело вакансій не годиться.

**Anthropic зараз коштує нуль.** Ключа в проді немає, обидва місця виклику
(`parse.ts`, `match.ts`) мовчки переходять на ключові слова.

## Ключове рішення: два класи «не-ATS»

Правило «посилання веде на роботодавця» лишається, але стає двоскладовим.

**Агрегатор** копіює вакансію, яка й так є на дошці роботодавця. Його
сторінка — передрук. Викидаємо, як зараз.

**Національний борд** — єдине місце, де вакансія існує. У DOU немає
«оригіналу на Greenhouse», бо його не існує. Викинути борд означає не
покривати країну взагалі.

Різниця не в домені, а в тому, чи є де-інде оригінал.

## Архітектура

### 1. Борд як рядок у таблиці, а не як код

У сканері вже є `rssSource(url, name, options)` — універсальний читач, ним
працюють WWR, NoDesk, Jobspresso. Тому **борд із RSS додається без коду**.

Нова таблиця:

```sql
CREATE TABLE country_boards (
    id         TEXT PRIMARY KEY,
    country    TEXT NOT NULL,          -- ISO-3166 alpha-2: UA, FR
    name       TEXT NOT NULL,          -- board:dou-ua
    feed_url   TEXT NOT NULL,
    kind       TEXT NOT NULL,          -- rss | api
    enabled    INTEGER NOT NULL DEFAULT 1,
    added_at   TEXT NOT NULL DEFAULT (datetime('now'))
);
```

`kind='rss'` обробляє наявний читач. `kind='api'` потребує власного коду —
такі додаємо поштучно, коли з'явиться попит (France Travail буде першим).

Вакансія дістає `jobs_cache.country`. Порожнє означає «глобальна».

### 2. Масштаб на всі країни

Двісті бордів наперед — це 190 мертвих рядків. Борд з'являється тоді, коли
з'являється людина з тієї країни.

- Тижневий самоперегляд додає правило `missing_country_board`: «троє людей
  із Польщі, польського борда немає».
- В адмінці — форма «додати борд»: країна, назва, адреса RSS. Без деплою.

Наперед засіваємо лише Україну (DOU, категорії, які нас стосуються).

### 3. Країна людини — три сигнали

| Порядок | Сигнал | Звідки |
|---|---|---|
| 1 | `profiles.location` | людина написала |
| 2 | `users.timezone` | збираємо на сайті вже зараз |
| 3 | нічого | лише глобальні джерела |

Другий сигнал уже лежить у базі й досі не використовувався.

Мапа поясів мала й навмисно неповна: лише пояси країн, для яких є борд.
Незнайомий пояс — це порожня країна, а не здогад.

**Ботові користувачі зараз усі мають `UTC`**, бо Telegram поясу не надсилає.
Тому крок «де хочеш працювати» питає місто, коли обрано «офіс у місті» або
«готовий переїхати».

### 4. Локація в неправильній розкладці

У базі лежить локація `зфкши`. Розкодована, вона дає `parib` — на одну клавішу
мимо `paris`. Тобто це «paris», набране на кирилиці, ще й з опискою.

`fixLayout(text)`: якщо рядок цілком кириличний і його переклад ЙЦУКЕН→QWERTY
дає відоме місто чи країну — беремо переклад (`зфкші` → `paris`, `дщтвщт` →
`london`). Інакше лишаємо як є.

Саме цей рядок ми НЕ рятуємо, і це рішення, а не недоробка: вгадувати описку
всередині помилкової розкладки означає підставити людині місто, якого вона не
писала. Країни в такого профілю не буде — це чесніше за вигадану Францію.

### 5. Підбір і добірка

- Вакансія з `country` йде лише людині з тією ж країною. Людині, чиєї країни
  ми не знаємо, національна вакансія не показується взагалі.
- Вакансія без `country` — усім, як зараз.
- Фільтр за країною стоїть У ЗАПИТІ вікна кандидатів, а не після відбору.
  Дошки дають близько шестисот свіжих вакансій на день; відсортовані за
  `posted_at`, вони заповнили б вікно з 1200 і випали б аж на підборі,
  лишивши людину з іншої країни майже без кандидатів. Це та сама пастка,
  що колись із `lever:jobgether`, тільки з іншого боку.
- У добірці пряме посилання на ATS роботодавця має перевагу; борд
  показується, коли кращого немає. Не жорсткий фільтр, а порядок.

### 6. Web3 — більше насіння, не нові дошки

Кураторський список слагів (Consensys, Paradigm та інші з екосистемних
каталогів) додається до наявного пробувальника ATS. Ніякого нового коду.

Superteam Earn не додаємо й фіксуємо чому: це біржа баунті.

## Панель витрат

### Що показуємо

**Anthropic.** Показуємо ТОКЕНИ, а не гроші: ставка за токен залежить від
моделі й змінюється, тож вигадане число на панелі власника виглядало б як
факт. Нова таблиця `api_usage`: час, служба, операція, токени входу
й виходу, вартість. Пишуть обидва місця виклику. Поки ключа немає — панель
каже це прямо, а не малює нулі як досягнення.

```sql
CREATE TABLE api_usage (
    id            TEXT PRIMARY KEY,
    at            TEXT NOT NULL DEFAULT (datetime('now')),
    service       TEXT NOT NULL,      -- anthropic
    operation     TEXT NOT NULL,      -- parse_profile | match_reason
    input_tokens  INTEGER NOT NULL DEFAULT 0,
    output_tokens INTEGER NOT NULL DEFAULT 0,
    cost_usd      REAL NOT NULL DEFAULT 0
);
```

**Сканування.** Скільки джерел опитано, скільки вакансій узято, скільки
запитів це коштувало — усе вже є в `scan_runs`, лишається показати.

**База.** Рядки в `jobs_cache`, читання й записи за добу.

### Чого свідомо не показуємо

Кількість запитів до Workers і D1 живе в аналітиці Cloudflare. Щоб її
показати на сторінці, довелося б покласти в воркер API-токен Cloudflare —
токен, який може значно більше, ніж прочитати лічильник. Число, яке видно в
панелі Cloudflare, не варте такого доступу. Замість цього на сторінці
посилання на панель Cloudflare.

## Вхід власника

Уже працює й міняти нічого не треба: `/admin` у боті видає разове посилання
на 15 хвилин, воно створює сесію на 30 днів і веде одразу в `/admin`.
Стороння людина цю команду не бачить — перевіряється збіг із `ADMIN_CHAT_ID`.

## Знайдене під час роботи

- **`\b` не працює з кирилицею.** Межа слова в JS рахується по латиниці, тож
  `/\bкиїв\b/` не збігається ніколи. Замінено на юнікодні межі `\p{L}`.
- **DOU має третій формат заголовка** — `Роль в Компанія, місто, віддалено`.
  Два наявні формати агрегаторів його не беруть, тож потрібен власний розбір
  із поділом по ОСТАННЬОМУ « в »: у назвах ролей це слово трапляється
  («Розробник в команду платежів»).
- **DOU кладе зарплату в той самий хвіст, що й місто.** Перша ж перевірка на
  живій стрічці дала вакансію з локацією `$1000–2000`. Вилку тепер забираємо
  в зарплату.
- **DOU чіпляє `?utm_source=jobsrss`** до кожного посилання — без очищення та
  сама вакансія з двох прогонів лягала б у кеш двічі.
- **Категорії DOU справді різні** — перетин між Legal, Design і Python
  нульовий. Тому засіваємо 24 категорії, а не одну загальну стрічку.
- **Web3-розвідка дала 34 живі компанії зі 169 кандидатів.** Троє з них —
  N26, Wise, Monzo — необанки, а не web3: позначені `fintech`. Правильний тег
  важливіший за розмір списку.

## Порядок робіт

1. Міграція 0010: `country_boards`, `jobs_cache.country`, `profiles.country`,
   `api_usage`
2. `fixLayout` і визначення країни за поясом
3. Читання бордів у сканері + засів DOU
4. Правила підбору й порядку в добірці
5. Крок «місто» в боті
6. Слаги web3
7. Правило `missing_country_board` у самоперегляді
8. Форма додавання борда в адмінці
9. Панель витрат

## Чого не робимо

- Не пишемо розбирачі HTML для дошок без RSS чи API — крихко й дорого.
- Не додаємо France Travail у цьому заході: потрібна реєстрація, якої я
  зробити не можу. Готуємо для нього `kind='api'` і повертаємось.
- Не знімаємо блокування Welcome to the Jungle: він передруковує.
